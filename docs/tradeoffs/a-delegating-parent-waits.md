# A delegating parent waits rather than blocks

**Gain:** a cell delegates without blocking. `rika.agents.spawn` admits a child and returns, and `rika.agents.inspectAll` waits up to a `waitMillis` the host clamps, so a parent can outlive the child it delegated to and use the answer. The wait ends as soon as every named child is terminal, and one that elapses reports the children as they are rather than failing. A parent that skips the wait races its children instead, which is why the lanes that read a child's terminal label wait for it.

**Cost:** a waiting parent occupies a scheduler slot for the length of its wait, and Baton's local scheduler runs at most `concurrency` Runs — four by default. A spawned child is moved to `running` the instant it is admitted rather than queued for later, so it competes for a slot before it has executed anything. Width is therefore real: a parent that waits on many children at once, or a Thread that delegates while its Title agent still runs, spends slots that nothing returns until those waits end. The bound is on how many Runs wait at the same moment, not on how deep a chain goes.

**Rejected:** blocking admission instead of polling would put a child's latency inside the parent's cell deadline, which is the failure the bounded wait exists to avoid. Raising the scheduler's concurrency trades memory and provider pressure for width without changing the shape, and the scheduler admits oldest-first, so added capacity reaches the shallowest Runs first. Releasing a slot for the duration of a wait belongs with Baton's execution host rather than a binding, because a Run that yields its slot must reclaim it without losing its cell's live namespace.

**Note on an earlier reading.** This document previously said delegation was dependable only one level deep, and derived a slot count to explain it. That arithmetic described a symptom. A spawned child that ran a cell died on the length of its own derived Session identity, which parked its Run and left the parent's wait to expire, and the failure looked like exhaustion because it only appeared when a child did enough work to reach the kernel. Two levels of delegation, each level calling a tool, is covered by `apps/rika/test/app.tui.test.ts` and fails when either half of that fix is reverted.
