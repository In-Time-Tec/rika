# Context compaction

Baton compacts an Execution when its pinned route approaches the context window, reserving the route's output allowance. Compaction is the only mechanism that bounds a conversation: no Rika agent pins a run budget, so an Execution is never stopped by accumulated model calls, tool calls, handoffs, or total tokens. Cumulative token counts charge every re-read of a cached prompt, so any budget on that dimension ends a long Execution while its live context is still small; Rika pins no such dimension and lets the context window plus compaction govern instead. Subagent depth and fan-out remain the only pinned execution limits, and they are enforced by Baton's tree policy rather than a budget. The TUI context meter measures the latest exact root input against the route's usable context window, changes tone as pressure rises, and animates while the execution is active. It first bounds old tool output, then keeps a recent token range, then creates a structured summary with the fixed GPT-5.6 Sol/xhigh summary route.

Compaction preserves the current prompt and durable transcript. The pinned policy and summary route pass through the Baton execution contract, so durable execution owns compaction state across restart and replay. Conversational and specialist agents can selectively call ReadThread to recover exact pre-compaction context from the retained transcript.
