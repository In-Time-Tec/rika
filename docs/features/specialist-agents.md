# Specialist agents

The main agent runs durable Task, Oracle, Librarian, Painter, Review, Surgeon, and ReadThread children from a cell through `rika.agents`. A spawn is admitted under a key derived from the ambient operation identity and the host ordinal, so a replayed cell cannot mint a second child and duplicate admission resolves to the same one. `rika.agents.inspect` reports a child's status and outcome immediately, `inspectAll` reports several and optionally waits up to a bounded `waitMillis` the host clamps and a cell may only narrow, returning whatever state the children are in rather than failing when it elapses, and `cancel` cancels a child. A suspended parent and child resume after restart, and a child that outlives its parent Execution is cancelled. Title is admitted by Rika, not from a cell. Task investigates the workspace and changes it only when assigned. Oracle is a read-only advisor for high-level planning, architecture tradeoffs, difficult debugging analysis, and review of focused, already-gathered evidence, not primary codebase exploration. Librarian handles substantive external documentation, repository, and codebase research, including current API or library behavior, public implementation examples, compatibility and release evidence, and cited source verification. Painter handles focused visual analysis. Surgeon reproduces and isolates a specific defect and may add temporary instrumentation. ReadThread searches current or historical local Thread transcripts and returns a grounded free-form answer.

Task and Surgeon use the selected mode's main route. Oracle, Librarian, Painter, and ReadThread use its Oracle route. Root has the seven declared child selections. Task has only Oracle, Librarian, Painter, ReadThread, and Surgeon; it never receives Task recursively. Every other child is a leaf. Child Runs use the parent manifest's pinned selection, route, and capability snapshot; cancellation and failure return Baton's explicit terminal child result rather than widening access.
