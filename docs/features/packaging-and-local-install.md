# Packaging and local installation

`bun run package -- --target <target>` builds one self-contained, versioned archive for `darwin-arm64`, `linux-arm64`, or `linux-x64`. A target is always explicit and a build replaces only that target's output. After all three producers finish, `bun run package -- --aggregate` validates the exact archive set without rebuilding and writes the sole `SHA256SUMS` and `release-evidence.json` under `artifacts`.

Before an exact TenetKit catalog version is published, `bun run local-tenetkit-smoke -- --tenetkit-release <directory>` validates TenetKit's exact thirteen-package release evidence and fourteen-entry checksum inventory. It copies the current Rika worktree into an isolated consumer, replaces the eight TenetKit packages Rika consumes with the matching tarballs, and performs a clean install, TenetKit-dependent package typechecks, host package, and packaged release smoke. The isolated lock must contain every consumed tarball and no npm TenetKit URL, and every installed manifest must exactly match its tarball. After the packaged smoke succeeds, the command copies that proven host archive into the source `artifacts` directory for `install-local`; tracked source manifests and the source lock remain unchanged.

An archive carries the four programs a Rika install needs, plus the two files a cell depends on: the kernel worker and a runtime to execute it. A compiled program cannot run another module and cannot resolve the one it was built from, and a machine that installed Rika has not necessarily installed Bun, so the worker and its runtime ship beside the binaries and the Server names them when the module path it would otherwise resolve is absent. `bun run release-smoke` runs a cell through the packaged binary with a deliberately bare `PATH` and asserts on a value the cell computed, so an archive whose kernel cannot start fails there rather than in a user's session.

`bun run install-local` installs an existing host archive under `~/.local/share/rika-dev/current` and links `~/.local/bin/rika-dev`; `RIKA_PACKAGE_TARGET`, `RIKA_INSTALL_ROOT`, and `RIKA_BIN_DIR` override target or paths. Installation replaces a prior owned source install but refuses to overwrite an unrelated command. `bun run uninstall-local` removes only the owned command and installed program, preserving Rika state and configuration.
