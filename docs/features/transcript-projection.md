# Transcript projection

The Thread Projection is disposable semantic read state derived from Rika product metadata and Generalist events. It stores stable keyed units, source order, revisions, model phase, cursor bounds, and a per-Turn checkpoint; assistant phases, native tool calls, Child Runs, images, and errors all use this one projection shape.

Applying source events is idempotent, and replacing a projection cannot move to an older revision. Event application and checkpoint advancement are atomic. If projection data is absent, stale, or incomplete, Rika rebuilds it from Generalist rather than treating it as execution truth.

Live patches update an indexed Thread view by changed Turn and unit keys. Full validation and materialization happen when a snapshot is opened, explicitly requested, or required after a revision gap; exact-next patches do not copy, sort, or revalidate unrelated history. The Generalist projector keeps a separate bounded recovery index for active Runs, tools, cards, authorizations, and compactions, so checkpoint serialization does not scan settled transcript units. A failed patch leaves the current revision and indexes unchanged and requests a resync instead of guessing.

Live model output is presented as a tentative overlay, not a projection revision. Generalist's memory-only bounded append frames synthesize segmented transient Reasoning and plain-source assistant units beside the durable transcript; completed segments retain terminal identity while only the append tail changes. Sequence or offset loss explicitly clears the affected Turn and marks that attempt incomplete, so later same-attempt frames cannot revive partial text. A newer attempt retires and clears the prior attempt even when its first observed frame is incomplete. Terminal status, a newer-generation scoped clear, resync, reconnect, or live-feed overflow replaces the overlay; an independently delivered durable unit cannot clear a later model call's preview. A generation-0 clear, which Generalist emits when it discards its memory-only frame on commit, instead holds the last tentative text mounted and closes that identity to late frames until the matching durable unit arrives and retires the overlay atomically, so the final answer never blanks between the clear and the durable patch. Pending local submissions are likewise an overlay: an echoed prompt survives snapshot and header-only patches until its durable prompt unit arrives.

Child Runs attach to the native child operation that requested them only through explicit `child_execution_id` and `invocation_id` event fields, and a delegated child is placed by its invocation origin's operation key and ordinal. Projection never parses a child Run ID for a parent execution or tool call, and event payloads use canonical snake-case keys rather than accepting historical aliases. When an ancestor Run settles terminal, the projector settles every still-open descendant Child Run as cancelled in the same revision, so a child never survives its parent as running in read state even when the follow stops at the parent's terminal event.
