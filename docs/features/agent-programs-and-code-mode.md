# Agent Programs and Code Mode

Code Mode creates a Baton Agent Program: JavaScript source that runs as a durable Program child of an Execution. The Program receives its input and a fixed capability object. It returns an object with a required `summary` string and optional JSON `data`.

The Program can discover or describe admitted tools, call an admitted tool or step, run one admitted Agent, map or fan out admitted Agents, and write a Program log. Rika currently admits no Program steps. The root Agent authorizes the complete set of Rika tools and the `Librarian`, `Oracle`, `Painter`, `ReadThread`, `Surgeon`, and `Task` Agent selections; each Program manifest narrows that authority to its declared tools and Agents.

At Turn admission, Baton persists the executable manifest and every required registration. The registration codecs are `rika-application-context`, `rika-model-route`, `rika-model-registry-route`, `rika-compaction`, `rika-tool`, `rika-program-sandbox`, `rika-program-input`, `rika-program-output`, and `rika-program-agent-input`. They contain the application context with the Workspace and resolved execution route; a model-route and model-registry route for Root, Title, Compaction, Oracle, Librarian, Painter, ReadThread, Review, Surgeon, and Task; the compaction policy; each tool name, description, and JSON schema; and the Program sandbox identity plus Program input, output, and Agent-input schemas. Model-route registrations retain credential references, such as the credential identity and environment-variable name. They never retain resolved credential values, API keys, tokens, authorization values, or passwords.

On restart, Baton resolves the persisted active executable and registrations. Rika rebuilds the scoped tool services from the persisted Workspace and verifies that every required registration is present and unchanged. It rejects extra, missing, changed, or non-admitted Program registrations. A Program cannot run under a different sandbox identity or Workspace.

Programs run in a new QuickJS runtime and context for each invocation. Guest source has no ambient filesystem, process, environment, network, module, or host-runtime authority. It can cross the boundary only through encoded capability calls. The persisted sandbox identity includes JavaScript, the `quickjs-singlefile-cjs-release-sync` implementation and version, the configured memory limit, the configured stack limit, and the Workspace. The production identity uses 64 MiB of memory and a 512 KiB stack.

Baton owns Program execution and its declared limits. Rika admits source up to 65,536 bytes and a budget of 16 Agent runs, four concurrent operations, 256 tool calls, 2,000,000 tokens, 600,000 milliseconds, 65,536 log bytes, and 262,144 output bytes. The QuickJS adapter applies the request wall-time and output-byte limits. Cancellation interrupts running and pending capability work, disposes the QuickJS resources, and reports Program cancellation rather than a successful result.

Rika accesses Baton execution through the five-operation `ExecutionGateway`: `startTurn`, `cancelTurn`, `steerTurn`, `watchTurn`, and `inspectTurn`. `startTurn` admits durable work and returns its opaque execution link. `cancelTurn` sends cancellation to Baton. `steerTurn` adds durable steering text with an idempotency key. `watchTurn` streams projected Run events from an optional cursor. `inspectTurn` reports the current status and cursor, or `unavailable` when Baton no longer has the Run.
