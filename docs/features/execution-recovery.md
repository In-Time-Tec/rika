# Execution recovery

On startup and reopen, Baton resumes persisted running Executions and Rika reconciles nonterminal Turns and stale read state against that durable authority. Rika inspects the durable Execution, backfills bounded event pages, then follows from the newest stored cursor; applying an event and advancing the projection checkpoint is idempotent. Server replacement abandons the old process-local observer without cancelling the durable Execution, then the new sole owner resumes observation.

Following stops at a Baton terminal event. Missing or interrupted transport never invents completion, and stale local terminal updates cannot replace a known terminal result. At startup and reopen, supervision also reconciles every nonterminal Turn against Baton authority: a Turn whose durable Execution no longer exists (for example after an incompatible Baton database rotation) is settled as failed with one idempotent `Execution unavailable` Error unit (classified `execution-unavailable`, never retried), instead of staying `running` forever and blocking queued work and clean cancellation. Turns with no Execution link (such as forked copies of active threads) and Turns whose Baton inspection is merely transiently unavailable are left untouched. A disposable projection or Thread summary may be rebuilt from Baton after loss or mismatch.
