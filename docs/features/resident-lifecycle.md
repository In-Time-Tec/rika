# Resident process lifecycle

The resident moves through `starting`, `ready`, `grace`, `draining`, and `stopped`. After the last client disconnects the resident lingers in `grace` (fifteen minutes by default, `RIKA_INTERNAL_RESIDENT_GRACE` overrides) so quick relaunches reattach warm instead of paying a cold spawn and product build. An authenticated client may cancel the grace period; clients arriving during draining are rejected, and startup detects incompatible residents, foreign listeners, unsafe tokens, and failed ownership rather than opening another state owner. A newly launched different build replaces the resident when its incompatibility response is authenticated. Reattaching clients never supersede: within the same compatibility epoch they attach to the replacement and keep their interactive runtime, while an authenticated epoch mismatch requires a runtime restart.

Quitting Rika cancels the work it was running. A quitting interactive client asks the resident to stop every non-terminal turn before the client process exits, so the durable stop intent survives an interrupted shutdown; the resident only honours that request when no other client is attached. A client that dies without warning cannot ask, so the resident treats the loopback connection as the liveness signal: once the last client detaches it waits `RIKA_INTERNAL_RESIDENT_ABANDON` (five seconds by default, never longer than the grace period) and, if no client has reattached and the resident is not draining for a replacement, records the stop intent and settles every non-terminal turn as cancelled. Reattaching inside that window cancels nothing, a resident that is being superseded never cancels, and settlement is idempotent because a stop intent that is not settled is settled by the next resident that starts.

The loopback listener stays owned until Relay and product SQLite close. Graceful shutdown bounds each client close and the server scope so signals can finish promptly. After an abrupt stop, the operating system releases the listener and the next resident relies on durable reconciliation rather than process memory.
