# Tool permissions

Rika runs local tools with the permissions of the user who started it and does not confine them to the Workspace. `shell` is the only configurable permission; specialist agents additionally receive only the capabilities required by their role. Workspace shell policy applies equally to shell commands entered by the user and shell calls requested by a model or Task agent: `allow` runs directly, `ask` waits for an explicit decision, and `deny` refuses without starting a process.

A hardcoded circuit breaker refuses recursive deletion of the filesystem root or the home directory and the shell fork bomb. It is not configurable and is not overridden by `allow` or `always`. It guards against catastrophic mistakes and is not a sandbox: a shell command can still reach anything the user can, so real isolation requires running Rika in a container. Only an explicit permission wait creates an actionable approval. Refusing the shell prompt or lacking a pinned capability returns a tool failure without running the operation, and cancellation ends the wait rather than granting access. A pending durable tool decision survives client restart, while a cancelled local shell prompt grants nothing and must be requested again.
