# Local and remote execution

Creating a Thread without a placement option creates a `local-device` Thread. Creating it with the explicit remote option creates an `e2b` Thread. Placement is durable and immutable; it is not encoded in Thread identity. An unavailable or disconnected Executor leaves the hosted Thread durable and visibly waiting instead of cancelling it or silently moving it. Local never falls back to E2B, and E2B never falls back to local.

The selected Executor owns Workspace access, kernels, coding tools, and processes. The API hosts TenetKit's PostgreSQL runtime, model loop, and encrypted provider credential use, then dispatches Workspace operations through TenetKit's stable remote-tool operation key. Hosted contracts carry opaque Workspace Identity rather than a host-local path; the Executor alone maps that identity to a path. The Executor connects outbound, accepts work only while holding the current assignment generation and lease epoch, durably deduplicates operation keys, and publishes resumable results. Every mutation includes both fences so a replaced Executor is rejected even if its old process is still running.

A local-device foreground executor advertises `pty: false`. It evaluates dispatched TypeScript cells in the shared persistent TenetKit kernel with Rika bindings mapped to the user's checkout. It does not accept, persist, or replay a live interactive PTY. Durable PTY sessions remain an E2B executor capability.

An E2B Executor receives a fresh Project checkout, runs repository setup, pauses without memory after fifteen idle minutes, and cold-resumes when authorized work arrives. Recovery uses committed TenetKit and API cursors, checkout identity, and verified workspace checkpoint artifacts; a replacement increments the assignment generation before accepting work. Full-memory provider snapshots are not a recovery path. No E2B controller credential reaches a CLI or TUI.
