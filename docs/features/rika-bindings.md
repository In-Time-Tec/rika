# rika bindings

Rika's capability surface reaches the model as `rika.*` host bindings mounted into the kernel, not as tool declarations. Twelve modules are mounted in a fixed order, and every mounted name is part of the bindings digest. Each operation validates its input and output against a Schema. A failed operation rejects the awaiting cell with its tagged failure value rather than an anonymous error, so a cell that catches gets a value it can branch on by `_tag`. An input or output that does not match its schema, and an unmounted module or operation name, are boundary failures reported by Baton rather than binding results.

`workspace` searches and reads the local filesystem and writes or replaces exact text, returning the same bounded text and unified diff the transcript renders. `edits.apply` applies between one and sixty-four replacements as one operation. `processes` starts one shell command with an optional working directory and initial wait, polls a still-running process for newly retained output, and stops a registered process. `web` searches the current web and reads a public page into bounded Markdown. `media.attach` inspects one local media file and returns its artifact metadata.

`threads` searches, finds, and reads bounded local Thread transcripts for the current Workspace. `context` reports the ambient Thread, Turn, Run, epoch, workspace, and trust mode, pages and searches canonical Session history, and lists compaction checkpoints; it can never append to history. `artifacts` stores one JSON value up to 8 MiB under a content-addressed id and loads it back, so a cell can hand a large value to a later cell without printing it. `harness` and `goal` own the continual harness and the Thread goal.

`agents` spawns, inspects, joins, and cancels durable Child Runs against the Oracle, Librarian, Painter, ReadThread, Review, Surgeon, and Task profiles, and sends and reads addressed messages. Parentage, sender identity, and the admission key are derived from the ambient operation identity, never from cell input, so a cell cannot forge a parent or mint a second child by replaying itself.

`mcp` lists configured servers and their tool schemas and calls one tool. Beyond that flat contract the bootstrap exposes `rika.mcp.<server>.<tool>(input)`, resolving names lazily against discovered tools; an unknown tool on a known server returns `McpBindingNotFound` as an ordinary value rather than rejecting, and an unknown or disabled server is unreachable.

Every call that crosses an authoritative or external boundary runs as a Baton nested durable operation, which is what carries its certainty and approval. `workspace.write`, `workspace.replace`, `edits.apply`, `process.start`, `process.stop`, `agents.spawn`, `mcp.call`, `harness.refine`, `goal.create`, and `goal.complete` are journaled and never replayed; `workspace.write`, `workspace.replace`, `edits.apply`, `process.start`, and `mcp.call` also declare an approval capability naming the path, paths, command, or server and tool, which no host currently answers, so a declared capability is approved without asking. `web.search`, `web.readPage`, `media.attach`, `artifacts.put`, and `agents.cancel` are journaled as provider-idempotent. Everything else — reads, searches, status polls, inspections, history, snapshots, and `goal.get` — runs inline with no journal entry.

The failure a cell sees for a nested operation is `NestedOperationFailed` with reason `divergence`, `unknown`, `denied`, or `suspended`. `unknown` means the operation crossed its boundary with an unobserved outcome and must be resolved explicitly.
