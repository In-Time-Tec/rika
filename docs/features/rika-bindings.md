# rika bindings

Rika's cell capability surface reaches the model as `rika.*` host bindings mounted into the kernel. Eleven modules are mounted in a fixed order, and every mounted name is part of the bindings digest. Each operation validates its input and output against a Schema. A failed operation rejects the awaiting cell with its tagged failure value rather than an anonymous error, so a cell that catches gets a value it can branch on by `_tag`. An input or output that does not match its schema, and an unmounted module or operation name, are boundary failures reported by Generalist rather than binding results.

`workspace` searches and reads the local filesystem and writes or replaces exact text, returning the same bounded text and unified diff the transcript renders. `edits.apply` applies between one and sixty-four replacements as one operation. `processes` starts one shell command with an optional working directory and initial wait, polls a still-running process for newly retained output, and stops a registered process. `web` searches the current web and reads a public page into bounded Markdown. `media.attach` inspects one local media file and returns its artifact metadata.

`threads` searches, finds, and reads bounded local Thread transcripts for the current Workspace. `context` reports the ambient Thread, Turn, Run, epoch, workspace, and trust mode, pages and searches canonical Session history, and lists compaction checkpoints; it can never append to history. `artifacts` stores one JSON value up to 8 MiB under a content-addressed id and loads it back, so a cell can hand a large value to a later cell without printing it. `harness` and `goal` own the continual harness and the Thread goal.

Child orchestration is deliberately outside the JavaScript cell boundary. Generalist's `run_child` and `run_child_group` tools own durable admission and suspension directly, so a JavaScript promise cannot pretend to be a restart-safe continuation.

`mcp` lists configured servers and their tool schemas and calls one tool. Beyond that flat contract the bootstrap exposes `rika.mcp.<server>.<tool>(input)`, resolving names lazily against discovered tools; an unknown tool on a known server returns `McpBindingNotFound` as an ordinary value rather than rejecting, and an unknown or disabled server is unreachable.

Railway classifies every hosted binding call before invoking the registry. This one policy owns its capability, side-effect class, replay policy, and approval requirement; an unclassified module or operation fails closed. Read-only calls need no approval. Workspace mutations, arbitrary terminal execution or control, Git commands, secret-bearing commands, publishing commands, and MCP calls require an exact Generalist approval. The approval request binds the authenticated actor, policy version, module and operation, arguments digest, Workspace, repository, branch, and current fenced Executor without including the command, prompt, cell source, or raw arguments. The binding's older nested declaration is bypassed at this hosted boundary, so the Railway classification produces the one durable nested operation that can authorize the effect.

Railway appends admission, approval-decision, and terminal-outcome evidence to PostgreSQL. Records contain only normalized identities, policy fields, arguments and checkpoint digests, decisions, and outcomes; they never contain raw secrets, prompts, commands, arguments, or cell source. An approval response must match the current projected authorization checkpoint and the exact safe request bound to the suspended operation. Audit rows are append-only evidence and are never read as execution authority. Personal audit reads require the Personal Owner's user. Organization audit reads reapply current membership and Thread or Project grants, including owner and admin break-glass access, so revocation immediately removes read access.

The failure a cell sees for a nested operation is `NestedOperationFailed` with reason `divergence`, `unknown`, `denied`, or `suspended`. `unknown` means the operation crossed its boundary with an unobserved outcome and must be resolved explicitly.
