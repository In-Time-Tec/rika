# Durable Execution mapping

Every Turn maps deterministically to one top-level Generalist Execution, and every Thread maps to one stable Generalist Session. Generalist owns execution events, waits, children, cancellation, replay, and terminal state; Rika stores the product records and disposable read projections that refer to them.

Generalist `runId` and `childRunId` values are opaque execution IDs. Rika does not add namespace prefixes or recover parentage from their text. Generalist persists each child invocation correlation in `ChildLinked`; projected child events carry the returned child Run ID and invocation ID, and every later inspect, replay, follow, cancel, or approval operation addresses that Run ID directly.

The Turn's resolved route and Workspace are supplied to exact root admission. Rika constructs one pinned executable and a complete immutable, secret-free registration set for that Turn, then calls Generalist `Runtime.start` with the route's pinned recursive tree policy; duplicate admission returns the same opaque Run link, while changed admission under the same Turn fails. Generalist persists the manifest, registration catalog, root depth, and tree policy atomically, so an admitted Execution restarts without reading Product rows, startup route maps, current configuration, the current directory, or fallback routes. Registration payloads contain provider connection and credential references, never resolved credential values; Rika's resolver dereferences those references through application credential services when reconstructing scoped execution resources.

At Turn admission, Generalist persists the executable manifest and every required registration. The registration codecs are `rika-application-context`, `rika-model-route`, `rika-model-registry-route`, `rika-compaction`, `rika-kernel-profile`, `rika-skill`, `generalist/instructions/snapshot`, and `rika-tool`. They contain the application context with the Workspace and resolved execution route; a model-route and model-registry route for Root, Title, Compaction, Oracle, Librarian, Painter, ReadThread, Review, Surgeon, and Task; the compaction policy; the admitted kernel profile; each pinned skill's name and digest, never its body; the continual-harness snapshot pinned under the `rika-harness-snapshot` capability; and the static `typescript` tool contract. Generalist's Execution Host supplies `run_child` and `run_child_group` dynamically when the persisted depth and active direct-child capacity permit them. Model-route registrations retain credential references, such as the credential identity and environment-variable name. They never retain resolved credential values, API keys, tokens, authorization values, or passwords.

On restart, Generalist resolves the persisted active executable and registrations. Rika reconstructs the same executable from the persisted application context and verifies that every required registration is present and unchanged. It rejects extra, missing, changed, or non-admitted registrations.

Rika accesses Generalist execution through the `ExecutionGateway`: `startTurn`, `cancelTurn`, `steerTurn`, `approveTurn`, `denyTurn`, `watchTurn`, and `inspectTurn`. `startTurn` admits durable work and returns its opaque execution link. `cancelTurn` sends cancellation to Generalist. `steerTurn` adds durable steering text with an idempotency key. `watchTurn` streams projected Run events from an optional cursor. Compact committed and interrupted model-response references are verified and hydrated through Generalist's public `Runtime.resolveModelResponse` operation before projection. Rika commits each streamed projection before delivering it once through the live callback; completion returns the latest durable state, units, and checkpoint without retaining or replaying historical changes. A recovery watch with no new events reads that result from the stored projection. Watch, projection-store, and inspection failures reconnect from the latest committed projector checkpoint with interruptible exponential backoff from 100 milliseconds to five seconds, resetting after committed progress. Silence and repeated deterministic defects are logged as projection failures and retried; they never request cancellation or author an execution outcome. A terminal change remains uncommitted and unpublished until a successful Generalist inspection reports the same terminal status and exact projector cursor; a terminal inspection ahead of the committed cursor triggers replay before Rika returns a coherent state, units, and checkpoint tuple. Consumer callback defects escape observation instead of being misclassified as transport recovery. Independently, terminal reconciliation inspects linked nonterminal Runs and writes the authoritative Generalist status to the Turn without reading or writing transcript projection. A terminal Turn whose transcript checkpoint is missing or still nonterminal remains eligible for projection recovery. `inspectTurn` reports the current status and required cursor for an available Run, or `unavailable` when Generalist no longer has the Run.

Every active execution observer also delivers Generalist's memory-only model preview append frames. Each frame has an attempt identity, a contiguous sequence, and bounded reasoning or answer changes whose offsets must equal the receiver's channel lengths. They are never written to Rika product tables or Generalist runtime tables, never advance a projector checkpoint, and disappear on disconnect or resync. A missing sequence, wrong offset, overflow, disconnect, or resync clears the affected Turn's tentative presentation; later frames from that incomplete attempt cannot revive it. A durable committed or interrupted response resolved from Generalist's Session is the only model output Rika persists.

Rika treats the Generalist and Effect versions pinned in the root package catalog as one runtime compatibility unit. They are installed and upgraded together so durable values never cross between different Effect runtime identities.
