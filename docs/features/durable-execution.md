# Durable Execution mapping

Every Turn maps deterministically to one top-level TenetKit Execution, and every Thread maps to one stable TenetKit Session. TenetKit owns execution events, waits, children, cancellation, replay, and terminal state; Rika stores the product records and disposable read projections that refer to them.

TenetKit `runId` and `childRunId` values are opaque execution IDs. Rika does not add namespace prefixes or recover parentage from their text. TenetKit persists each child invocation correlation in `ChildLinked`; projected child events carry the returned child Run ID and invocation ID, and every later inspect, replay, follow, cancel, or approval operation addresses that Run ID directly.

The Turn's resolved route and Workspace are supplied to exact root admission. Rika constructs one pinned executable and a complete immutable, secret-free registration set for that Turn, then calls TenetKit `Runtime.start` with the route's pinned recursive tree policy; duplicate admission returns the same opaque Run link, while changed admission under the same Turn fails. TenetKit persists the manifest, registration catalog, root depth, and tree policy atomically, so an admitted Execution restarts without reading Product rows, startup route maps, current configuration, the current directory, or fallback routes. Registration payloads contain provider connection and credential references, never resolved credential values; Rika's resolver dereferences those references through application credential services when reconstructing scoped execution resources.

At Turn admission, TenetKit persists the executable manifest and every required registration. The registration codecs are `rika-application-context`, `rika-model-route`, `rika-model-registry-route`, `rika-compaction`, `rika-kernel-profile`, `rika-skill`, `@tenetkitfx/harness/snapshot`, and `rika-tool`. They contain the application context with the Workspace and resolved execution route; a model-route and model-registry route for Root, Title, Compaction, Oracle, Librarian, Painter, ReadThread, Review, Surgeon, and Task; the compaction policy; the admitted kernel profile; each pinned skill's name and digest, never its body; the continual-harness snapshot pinned under the `rika-harness-snapshot` capability; and the static `typescript` tool contract. TenetKit's Execution Host supplies `run_child` and `run_child_group` dynamically when the persisted depth and active direct-child capacity permit them. Model-route registrations retain credential references, such as the credential identity and environment-variable name. They never retain resolved credential values, API keys, tokens, authorization values, or passwords.

On restart, TenetKit resolves the persisted active executable and registrations. Rika reconstructs the same executable from the persisted application context and verifies that every required registration is present and unchanged. It rejects extra, missing, changed, or non-admitted registrations.

Rika accesses TenetKit execution through the `ExecutionGateway`: `startTurn`, `cancelTurn`, `steerTurn`, `approveTurn`, `denyTurn`, `watchTurn`, and `inspectTurn`. `startTurn` admits durable work and returns its opaque execution link. `cancelTurn` sends cancellation to TenetKit. `steerTurn` adds durable steering text with an idempotency key. `watchTurn` streams projected Run events from an optional cursor. Compact committed and interrupted model-response references are verified and hydrated through TenetKit's public `Runtime.resolveModelResponse` operation before projection. Rika commits each streamed projection before delivering it once through the live callback; completion returns the latest durable state, units, and checkpoint without retaining or replaying historical changes. A recovery watch with no new events reads that result from the stored projection. Watch, projection-store, and inspection failures reconnect from the latest committed projector checkpoint with interruptible exponential backoff from 100 milliseconds to five seconds, resetting after committed progress. A deterministic projection defect — a die that repeats without committed progress — is not healable by replay, so after three consecutive defect attempts the watch terminalizes the Turn as failed, commits a non-retryable projection-defect unit, and returns that terminal result instead of reconnecting forever. A terminal change remains uncommitted and unpublished until a successful TenetKit inspection reports the same terminal status and exact projector cursor; a terminal inspection ahead of the committed cursor triggers replay before Rika returns a coherent state, units, and checkpoint tuple. Consumer callback defects escape observation instead of being misclassified as transport recovery; they originate in the observer, never terminalize an Execution-linked Turn, and do not advance its pending queue. Projection-path defects are different: a defect raised while projecting the Run stream belongs to the projection itself and terminalizes the Turn under the bounded-defect rule above. `inspectTurn` reports the current status and required cursor for an available Run, or `unavailable` when TenetKit no longer has the Run.

Every active execution observer also delivers TenetKit's memory-only model preview append frames. Each frame has an attempt identity, a contiguous sequence, and bounded reasoning or answer changes whose offsets must equal the receiver's channel lengths. They are never written to `rika.db` or `tenetkit.db`, never advance a projector checkpoint, and disappear on disconnect or resync. A missing sequence, wrong offset, overflow, disconnect, or resync clears the affected Turn's tentative presentation; later frames from that incomplete attempt cannot revive it. A durable committed or interrupted response resolved from TenetKit's Session is the only model output Rika persists.

Rika treats the TenetKit and Effect versions pinned in the root package catalog as one runtime compatibility unit. They are installed and upgraded together so durable values never cross between different Effect runtime identities.
