# Durable Execution mapping

Every Turn maps deterministically to one top-level Generalist Execution, and every Thread maps to one stable Generalist Session. Generalist owns Runs, model turns, operations, waits, blocking children, cancellation, replay, recovery, and terminal state. Rika stores product records and disposable read projections that refer to them.

Rika admits one pinned executable and immutable, secret-free registration set for each Turn. The registration codecs include the application context, model routes, compaction policy, skills, native tool policies, continual-harness snapshot, and Generalist instruction snapshot. The model-visible workspace toolkit is exactly `bash`, `edit`, `read`, and `shell_command_status`. Generalist supplies `run_child` and `run_child_group` dynamically when the persisted tree depth and direct-child capacity allow them. Credential registrations retain references only and never retain resolved keys, tokens, authorization values, or passwords.

On restart, Generalist resolves the persisted executable and registrations. Rika reconstructs the same executable from persisted application context and rejects missing, extra, changed, or non-admitted registrations. Rika accesses execution through `ExecutionGateway`: start, cancel, steer, approve, deny, watch, and inspect. A watcher commits each projected revision before delivery and reconnects from the latest committed checkpoint.

Local and Orb tools share one durable routing contract. The outer Generalist operation identity, attempt, tool-call identity, and fenced machine assignment determine one machine request. Accepted, started, output, and terminal lifecycle frames are persisted. Reconnect replays a retained `MachineExecute` only when its replay policy permits it. While cancelling, reconnect replays `MachineCancel` and waits for `MachineResult`. Completed, failed, cancelled, conflicted, and unknown terminals remain stable across reconnect and restart.

The outer remote call is provider-idempotent because its stable operation key addresses one durable Rika operation. That does not make the underlying machine effect safe to repeat. Read and status machine operations are replayable, while an unobserved `bash` or `edit` terminal is persisted as unknown and is never rerun blindly. After Rika observes that terminal unknown, it records a separate never-replay Generalist marker, so the Run enters Generalist-owned resolution without changing the replay policy of the outer call. Transport loss before a terminal unknown creates no marker and reattaches to the same outer operation. The agent must inspect durable process or Workspace state before making a different call.

Child Runs use Generalist's unchanged blocking `run_child` and `run_child_group` operations. Parent suspension, child settlement, cancellation, and resumption remain Generalist-owned. Rika projects neutral ordered subagent cards and never creates a second join protocol.
