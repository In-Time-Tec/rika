# Diagnostics

Clients and the server write private Effect JSON logs below the Profile data root. Records contain bounded operation names, process roles, safe identifiers, state transitions, durations, and typed failure kinds. They exclude prompts, model bodies, tool arguments and output, shell content, headers, credentials, and arbitrary error messages.

Diagnostic path, status, and export commands work without starting the server. Normal shutdown flushes scoped logs; abrupt termination may leave an open file as crash evidence. Headless runners (`--no-tui`) persist the same stream, so an unattended Runner is as debuggable as an interactive one.

The Runner stream covers the full execution protocol: transport lifecycle and reconnects, cell admission and settlement, binding sends and results, and kernel-level cell events — every host binding call (`runner.kernel.host_call` with module, operation, status, and duration), kernel starts and restarts with their reason (`runner.kernel.starting`, `runner.kernel.restarted`), state restore and loss (`runner.kernel.state_restored`, `runner.kernel.state_lost`), and a no-progress warning (`runner.kernel.cell.no_progress`) when a running cell has produced no events for 30 seconds. A tool call that stalls therefore leaves a visible trail: the last host call before the silence, repeated no-progress warnings, and the deadline or restart that eventually ends it.
